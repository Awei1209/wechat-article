## 📌 这个项目做什么？

写公众号文章通常要经历：

```
想选题 → 找素材 → 搭框架 → 写正文 → 想标题 → 配图 → 排版 → 发布
```

每一步都可能卡住。

**这个工作流把整个流程自动化了。** 你只需要说一句「写一篇公众号」，AI 就会：

1. 给你选题建议（可选交互）
2. 自动搜索真实素材
3. 选择最合适的写作框架
4. 写出 1500-2500 字的完整文章
5. 优化标题、摘要、标签（SEO）
6. 生成配图提示词
7. 输出排版好的格式
8. 给出发布说明

每一步都能降级：即使某个能力不可用（比如搜索被限制），其他步骤继续运行，不会整体崩溃。

## 🚀 快速开始（5分钟上手）

### 第一步：理解工作原理

```
你说 "写一篇公众号" 
  → AI 读取 longwrite/SKILL.md 
  → 按 8 个 Step 依次执行
  → 输出：文章 + 标题 + 摘要 + 标签 + 配图提示词 + 排版格式
```

### 第二步：首次使用（Onboard）

第一次使用时，AI 会问你 6 个问题，建立你的「写作风格配置」：

| 问题 | 作用 |
|------|------|
| 账号/作者名 | 文末署名 |
| 目标平台 | 公众号/博客/知乎，影响排版格式 |
| 目标读者 | 影响语言风格和案例选择 |
| 主战主题 | AI 在选题时围绕你的主题推荐 |
| 语气与人设 | 朋友聊天 / 行业观察 / 犀利评论 |
| 黑名单 | 不想出现的词（比如"赋能"、"颠覆"） |

回答后，AI 生成 `style.yaml` 文件保存配置。之后再说「写一篇公众号」，就直接跑完全程，不需要重复确认。

### 第三步：开始写文章

最简单的一句话：

```
写一篇公众号
```

AI 会全自动跑完 Step 1-8，输出完整结果。

如果你想自己选话题/框架/配图：

```
写一篇公众号，选题时停一下让我确认
```

## 🔄 两种运行模式

### 全自动模式（默认）

一口气跑完 Step 1-8，不中断。只有在出错时才停。

```
你说："写一篇公众号"
AI：直接给你完整文章 + 标题 + 配图 + 排版
```

**适合：** 已经有明确方向，只想快速出稿。

### 交互模式

在「选题 / 框架 / 配图」三个节点暂停，等你确认。

```
你说："写一篇公众号，交互模式"
AI：列出 8-12 个选题 → 你选一个
AI：列出 2-3 个推荐框架 → 你选一个
AI：生成 3 套封面方案 → 你选一个
AI：继续写完剩余步骤
```

**适合：** 想把控文章方向，或者想学习不同框架的区别。

**切换方式：**
- "交互模式" / "我想自己选" → 开启交互
- "全自动" / "直接写" → 关闭交互

## 📋 8 步管道详解

### Step 1：环境 + 配置

**做什么：**
1. 读取你的 `style.yaml`（写作风格配置）
2. 检测三个能力是否可用：
   - WebSearch（搜索素材）
   - 图像生成（AI 画图）
   - 发布能力（草稿箱/API）

**降级标记：**
- 如果没有图像生成器 → `skip_image_gen=true`，Step 6 只输出文字提示词
- 如果没有发布能力 → `skip_publish=true`，Step 7 输出「可复制粘贴」的格式
- 如果搜索被限制 → `skip_websearch=true`，用常识和用户提供的信息写

**输出：** 三个降级标记 + 风格配置

---

### Step 2：选题

**做什么：** 生成 8-12 个候选选题，每个包含：
- 标题
- 角度（怎么切入）
- 推荐框架
- 风险提示（可能引发争议/数据不足等）

**评分维度：**
- 点击率潜力（标题有没有冲击力）
- SEO 潜力（有没有可搜索的关键词）
- 可写性（素材够不够）
- 与账号定位的匹配度（参考 style.yaml）

**如果 `skip_websearch=false`：**
AI 会实际搜索热点、趋势、背景材料来支撑选题。

**如果 `skip_websearch=true`：**
AI 基于公开常识生成选题，并在每个选题后标注「建议补充真实数据来源」。

---

### Step 3：框架 + 素材

**做什么：**

1. **选框架**：从 `frameworks.md`（7套框架）中选最合适的
2. **采集素材**：搜索真实信息，每条标注来源

**7 套写作框架：**

| 框架 | 适合主题 | 结构 |
|------|---------|------|
| 痛点-方案 | 工具/方法论/效率 | 痛点 → 原因 → 方案 → 坑 → 收尾 |
| 清单（How-to）| 教程/可操作干货 | 按步骤/要点编号，每点含做法+原理+例子 |
| 对比评测 | 两种工具/路线对比 | 结论 → 维度对比 → 场景建议 → 踩坑 |
| 热点解读 | 热点事件/行业新闻 | 事实 → 利益方 → 观点 → 角度 → 预测 |
| 纯观点 | 评论/观点文章 | 一句话观点 → 3个论据 → 反方论据 → 反驳 → 收尾 |
| 故事 | 人物/个人经历/案例 | 冲突开场 → 转折 → 细节 → 复盘 |
| 复盘 | 项目/失败复盘 | 目标 → 过程 → 偏差 → 原因 → 改法 |

**素材清单标准（每篇 5-8 条）：**
```
- 来源：URL / 媒体名 / 作者 / 时间
- 可引用片段：数据 / 引述 / 案例
- 可信度备注
```

**输出：** 带素材锚点的大纲（每个 H2 下面标注将插入哪条素材）

---

### Step 4：写作

**做什么：** 根据大纲 + 素材，写出完整文章

**写作规则（底线）：**
- 字数：1500-2500 字
- 结构：H1 标题 + 3-6 个 H2
- **必须包含 2-3 个编辑锚点**（见下方）
- 每个 H2 至少引用 1 条真实素材（零编造）

**编辑锚点（让 AI 文章变成「你的作品」）：**
```html
<!-- ✏️ 编辑建议：在这里加一句你自己的经历/看法 -->
```
这是模板最关键的设计：AI 出初稿，你补充真实经历，两句话就能让文章完全不一样。

**禁止的词：**
- 赋能、闭环、抓手、对标、降维打击、颠覆性、All in
- "大家都知道"、"众所周知"、"不难发现"（空话引导）

**开头规则（前 3 句必须满足至少一项）：**
- 反常识 / 反直觉
- 具体冲突（"我差点因为 X 做错了 Y"）
- 明确收益（"看完你会得到 3 个可复制的方法"）

**禁止用背景铺垫开头**，不要写"近年来/随着社会发展/在 XX 背景下..."连写 5 句。

---

### Step 5：SEO + 质量验证

**做什么：** 优化标题、生成摘要和标签，并验证文章质量

**输出：**
- **3 个备选标题**（20-28字，含关键词）
- **摘要**（≤40字，不是概括而是"点击理由"）
- **5-8 个标签/关键词**（3个核心词 + 2-5个长尾词）

**标题模板：**
```
【反直觉】"你以为 X 很难，其实卡在 Y"
【清单】"用 X 做 Y：5 个步骤 + 2 个坑"
【对比】"A vs B：我为什么最终选了 C"
【热点】"X 事件背后，真正改变的是 Y"
```

**质量验证（定向修复，不整篇重写）：**
- 找到具体不达标的句子/段落
- 每轮最多改 1-3 处
- 立刻复检该项

---

### Step 6：视觉内容

**做什么：** 生成封面 + 内文配图的提示词

**封面：** 输出 3 套方案，每套包含：
- `prompt`：画面描述
- `negative_prompt`：不希望出现的元素
- `style_anchor`：色板/风格关键词（后续内文图复用）

**内文配图：** 3-6 张，类型包括：
- 流程图（流程步骤类文章）
- 对比图（对比评测类文章）
- 时间线（热点解读类文章）
- 场景图（故事/观点类文章）

**如果 `skip_image_gen=true`：**
只输出文字提示词（你复制到豆包/即梦生成图片）。

---

### Step 7：排版 + 发布

**做什么：** 输出排版好的格式

**如果 `skip_publish=true`（无发布 API）：**
输出两份格式：
1. 纯 Markdown（保真）
2. 平台友好格式（可直接粘贴到公众号编辑器）

手动发布说明：
1. 复制排版好的内容
2. 打开微信公众号后台
3. 新建图文消息
4. 粘贴，插入配图
5. 点击「一键排版」
6. 保存草稿，预览，发布

**如果有无障碍发布的 API：**
直接调用发布接口，自动写入草稿箱，输出草稿链接。

---

### Step 8：收尾 + 复盘

**最终回复包含：**
- 本次选择的：选题 / 框架 / 写作策略（简要）
- 本次降级项（如有）：`skip_websearch / skip_image_gen / skip_publish`
- 下一步入口：
  - "检查一下" → 输出质量报告（面向修改建议）
  - "学习我的修改" → 启动风格飞轮（把你的编辑反哺到规则库）

## 🔧 如何定制成你自己的 Skill

这个模板是通用的，你可以按业务需求修改 5 个地方：

### 1）改 Skill 名称与触发词

编辑 `longwrite/SKILL.md` 顶部的 YAML：

```yaml
---
name: 你的skill名称
description: |
  触发关键词：公众号、推文、草稿箱、排版、选题
  不应触发：写邮件、写周报、写PPT
---
```

### 2）改目标平台参数

在 `onboard.md` 里加入平台字段，生成到 `style.yaml`：

```yaml
platform: "wechat"   # 或 "zhihu" / "blog" / "newsletter"
```

平台不同，Step 5（SEO）和 Step 7（排版）的规则也不同：
- **公众号**：标题≤32字、摘要≤120字、标签体系、微信兼容排版
- **知乎**：长标题、问题导向
- **博客/Newsletter**：Markdown 原样输出，排版需求更轻

### 3）接入真实数据源

**方式 A：** 继续用 WebSearch（默认）
- 优点：简单
- 风险：某些环境/域名可能被限制

**方式 B：** 换成你的内部知识库 API
- 在 Step 3 "素材采集"处调用你的 API
- 输出统一的「素材清单」格式

**方式 C：** 离线模式
- 让用户提供链接/文件/要点
- 或从指定目录读取本地文件

### 4）接入图像生成（可选）

- 有图像生成器 → 在 Step 6 加入生成调用，图片与插入位置绑定
- 无图像生成器 → `skip_image_gen=true`，Step 6 只输出文字提示词

### 5）接入发布 API（可选）

- 有草稿箱 API → 调用 API 发布，输出草稿链接
- 无 API → `skip_publish=true`，Step 7 输出手动发布说明

## ❓ 常见问题

**Q：这个和直接让 AI 写文章有什么区别？**

直接让 AI 写，往往质量不稳定（废话多、开头铺垫、结尾喊口号）。
这个工作流有明确的框架约束、素材锚定、编辑锚点，输出更可控、更接近「专业编辑」的质量。

**Q：编辑锚点是什么？**

`<!-- ✏️ 编辑建议：在这里加一句你自己的经历/看法 -->`

AI 在写文章时会主动留「缺口」，提示你在哪里补充真实经历。两句话的补充，就能让 AI 文章变成你的作品。

**Q：没有搜索能力怎么办？**

设置 `skip_websearch=true`，AI 基于常识和公开信息写作，并在素材不足的地方标注风险。写作质量可能受影响，但整体流程不受阻碍。

**Q：能用在其他平台吗？**

可以。修改 `onboard.md` 和 `seo-rules.md` 里的平台参数即可支持：知乎、博客、微博、Newsletter 等。

**Q：style.yaml 在哪里？**

根据你的安装方式，可能在：
- `~/.qclaw/skills/longwrite/style.yaml`
- 或 Skill 所在目录的 `style.yaml`

直接对 AI 说「查看我的写作风格配置」也能获取当前内容。
