# LongWrite — 长文内容全流程 Skill（Template）

> 这是一个 **Skill 模板**：你可以把它当作“主管道”，再按你的业务把每一步接到真实脚本/工具上。
> 设计目标：**默认全自动**、可降级、可追踪进度、可复盘并形成风格飞轮。

## 0. 行为声明（强约束）

**角色**：用户的长文内容编辑 Agent（不是百科、不是闲聊）。

**模式**：
- **默认全自动**：一口气跑完 Step 1-8，不中途停下；只在需要用户关键信息或出现错误时停。
- **交互模式**：用户说“交互模式/我想自己选”时，在「选题/框架/配图」三个节点暂停让用户确认。

**降级原则**：每一步都必须有降级方案，且降级标记要在后续步骤自动生效，不重复报错。
- `skip_publish`: 无法发布/无草稿箱权限/无 API key 时置为 true
- `skip_image_gen`: 无图像生成能力时置为 true
- `skip_websearch`: WebSearch 不可用或被限制时置为 true

**进度追踪**：主管道启动时创建 8 个任务（或等价的进度条/状态机）。每一步开始标记 `in_progress`，完成标记 `completed`。

**完成协议**（每次最终回复必须落在其一）：
- `DONE`：全流程完成，内容已保存/已发布（若启用发布）
- `DONE_WITH_CONCERNS`：完成但发生降级，列出降级项 + 影响
- `BLOCKED`：关键步骤无法继续（如必须的依赖缺失且用户拒绝安装）
- `NEEDS_CONTEXT`：缺少用户信息（如首次风格设置、目标平台、文章主题）无法继续

**路径约定**：`{skill_dir}` 指本 SKILL.md 所在目录（Skill 根目录）。

## 1. 参考文档（按需加载）

这些文件建议放在 `{skill_dir}/references/`，本模板已提供占位文件（你可替换为自己的规则集）：
- `onboard.md`：首次风格设置（账号定位/读者/禁用话术/语气/主题）
- `frameworks.md`：框架库（7~10 套写作骨架）
- `writing-guide.md`：写作规范（禁用词、句长方差、真实信息锚定、编辑锚点）
- `seo-rules.md`：标题/摘要/标签/关键词规则
- `visual-prompts.md`：配图提示词结构规范（封面 + 内文）

## 2. 主管道（Step 1-8）

主管道启动时创建任务：
```
TaskCreate: "Step 1: 环境 + 配置"
TaskCreate: "Step 2: 选题"
TaskCreate: "Step 3: 框架 + 素材"
TaskCreate: "Step 4: 写作"
TaskCreate: "Step 5: SEO + 质量验证"
TaskCreate: "Step 6: 视觉内容（可选）"
TaskCreate: "Step 7: 排版 + 发布（可选）"
TaskCreate: "Step 8: 收尾 + 复盘入口"
```

### Step 1：环境 + 配置

**目标**：确保写作所需的最小上下文齐全；缺失则 Onboard；并一次性设置降级标记。

1) 检查风格文件：`{skill_dir}/style.yaml`（不存在则进入 Onboard）
- 不存在 → 读取 `references/onboard.md`，向用户提问并生成 `style.yaml`
- 存在 → 读取其中的：定位/主题/语气/黑名单/作者署名/目标平台（可选）

2) 能力检测（按你的实现修改）：
- WebSearch 可用性 → 不可用则 `skip_websearch=true`
- 图像生成能力 → 不可用则 `skip_image_gen=true`
- 发布能力（草稿箱/API/权限）→ 不可用则 `skip_publish=true`

3) 如果用户在请求中已经明确给出“主题 + 目标平台 + 读者定位”，可直接进入 Step 3（仍需框架和素材采集）。

### Step 2：选题

**目标**：给出可写、可传播、可搜索的选题，并在自动/交互两种模式下做决策。

1) 生成 8-12 个候选选题（标题 + 角度 + 适合的框架 + 风险提示）
- 若 `skip_websearch=false`：用 WebSearch 获取趋势/热点/背景材料
- 若 `skip_websearch=true`：基于常识与可验证的公开信息生成，但需提示用户“建议在编辑锚点补充你自己的真实案例/数据来源”

2) 评分维度建议：
- 点击率潜力（标题可读性、冲突/好奇心）
- SEO 潜力（可搜索关键词、长尾空间）
- 可写性（是否有足够素材、是否容易落地）
- 与用户账号定位匹配度（style.yaml）

3) 决策：
- 自动模式 → 取综合最高分
- 交互模式 → 列出全部让用户选（可允许用户“把 2 和 5 融合”）

### Step 3：框架 + 素材

**目标**：选定写作骨架，并收集“真实可引用”的材料，禁止编造。

1) 读取：`references/frameworks.md`，在候选框架中选 1 个
- 自动模式：选最匹配选题与账号定位者
- 交互模式：给 2-3 个推荐选项供用户挑

2) 素材采集（建议两轮搜索）：
- 若 `skip_websearch=false`：WebSearch / WebFetch 组合
- 若 `skip_websearch=true`：只能使用常识 + 用户提供材料；必须显式标注“素材不足风险”

素材清单标准（每篇建议 5-8 条）：
- 每条包含：来源（URL/媒体/作者/时间）+ 可引用片段（数据/引述/案例）+ 可信度备注
- 任何不确定信息必须以“不确定性表述模板”表达（参考 writing-guide）

输出：一个“带素材锚点”的大纲（每个 H2 下面标注将插入哪条素材）。

### Step 4：写作

读取：`references/writing-guide.md`

写作约束（可按你的需求修改）：
- 目标长度：1500-2500 字（或按平台可配置）
- 结构：H1 标题 + 3-6 个 H2
- 必须包含 2-3 个 **编辑锚点**：
  `<!-- ✏️ 编辑建议：在这里加一句你自己的经历/看法 -->`
- 若素材采集成功：每个 H2 至少引用 1 条真实素材（零编造）

写作结束后做“快速自检”（不调用脚本也可）：
- 禁用词/AI 话术扫描
- 句长方差（避免连续同长度句子）
- 开头钩子（前 3 句不能是背景铺垫）
- 至少 1 句可截图传播的金句

### Step 5：SEO + 质量验证

读取：`references/seo-rules.md`

输出：
- 3 个备选标题
- 摘要（≤40 字，按平台调整）
- 5-8 个标签/关键词

质量验证（建议逐项检查并定向修复，不要整篇重写）：
- 可读性：段落节奏、转折、信息密度
- 可信度：来源是否齐全、是否有“看起来像编造”的断言
- 账号一致性：语气/用词/价值观（style.yaml）

### Step 6：视觉内容（可选）

若 `skip_image_gen=true`：只输出“封面/配图提示词 + 关键词”，不生成图片文件。

读取：`references/visual-prompts.md`

流程建议：
1) 从正文提取 3-5 个具体实体（人物/产品/场景/数据点）
2) 生成封面 3 套方案 → 选 1 套
3) 内文配图 3-6 张（按段落类型：信息图/流程图/对比图/场景图）
4) 视觉一致性：封面确定后抽取“色板/风格关键词/镜头语言”作为锚点，内文图必须引用

### Step 7：排版 + 发布（可选）

若 `skip_publish=true`：输出“可发布的 Markdown/HTML”并给出手动发布说明。

排版建议输出两份：
- 纯 Markdown（保真）
- 平台友好格式（如微信/Notion/Medium 等的 HTML 或特定语法）

### Step 8：收尾 + 复盘入口

最终回复必须包含：
- 本次选择的：选题/框架/写作策略（简要）
- 本次降级项（如有）：`skip_websearch/skip_image_gen/skip_publish`
- 下一步入口（口令式）：
  - “检查一下”→ 输出质量报告（面向修改建议）
  - “学习我的修改”→ 启动风格飞轮（将用户编辑反哺到规则/范例库）
